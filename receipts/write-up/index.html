Receipts write-up: what we tested, the tally, and what broke

Lantern Works tested 86 MCP servers by installing each one, giving it a specific task, and checking the output against an independent ground truth. This page's counts, date list, and broken-case list are computed from the Receipts index when the site is built, not typed in by hand. The records themselves are dated 29 October 2026, 31 October 2026, and 20 November 2026 (37 on 29 October 2026, 25 on 31 October 2026, and 24 on 20 November 2026; 86 in all). Only dates that appear in the records are listed; no days in between are filled in.

The full record list is the Receipts index. Machine-readable records: /api/v1/receipts.json.

What we tested

This edition has 86 records: 1 house product, 20 reference, and 65 community. Install sources in the index are 47 npm, 33 pypi, and 6 other. Each record names the version tested, the canonical task, the ground truth it was graded against, and a headline finding.

Record #000 is the Lantern Works house product, lantern-works-deals-mcp version 0.3.8, tested 2026-10-29. It is not an independent endorsement of today's release. See the index entry.

Counts below are the number of records for each recorded verdict value in the Receipts index. The index page uses slightly different display wording for the same keys: “Worked” for works, “Worked with caveats” for works_with_caveats, “Failed tested task” for broken, and “Deferred — needs credentials” for deferred.

Deferred means the promised task was not tested, not that the server is broken. Credential-gated tests used decoy credentials, so successful authenticated workflows were not tested.

What broke

33 of 86 records have the recorded verdict broken (failed the dated, scoped task). Findings are the authored headlines and caveats from the index; they are not security certifications or current compatibility guarantees.

#008 wikipedia-mcp

wikipedia-mcp v2.0.1 · tested 2026-10-29

Returns summary: null with isError: false behind any HTTP proxy — its HTTP library discards proxy settings and the failure is invisible to the calling agent.

Task: fetch the summary of the article 'Lantern' and search for it

  • Root cause: the wikipediaapi dependency builds its httpx client with an explicit transport, discarding environment proxy config; no server option exists to fix it (scoped: broken on proxy-egress networks; direct egress unobservable from this sandbox)
  • Failure is reported as success: summary null, isError false, 'error' field containing only the bare API URL
  • tools/list registers all 22 tools twice (bare and wikipedia_-prefixed); serverInfo reports version 4.1.4 vs package 2.0.1
